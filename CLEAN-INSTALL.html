Install Orbital on IONOS

Six steps, in order, all in the browser. About twenty minutes the first time. Every step is safe to repeat, and nothing here deletes your data. Tick each step as you go; the ticks are saved in this browser.

HOW

How the pieces fit. Supabase holds the data. GitHub runs the daily scrape and, on every upload, publishes the site to your IONOS web space over SFTP. IONOS serves jobs.lisaney.com. You set each one up once; after that, uploading files to GitHub is the only thing you ever do.

  1. Set up the databasesupabase.com

    One paste creates or updates all six tables. It keeps every job, application and note you already have, so it is also the upgrade step for later builds.

    • Open SUPABASE-SCHEMA.sql from this kit in any text editor, select all, copy
    • Go to supabase.com/dashboard and open your Orbital project
    • Left sidebar → SQL Editor → + New query
    • Paste, then click Run (or Ctrl + Enter)
    • Left sidebar → Table Editor: check the six tables are listed

    Stay on the same Supabase project. orbital-config.js already points at it.

    Expect

    "Success. No rows returned", and six tables: jobs, user_state, scrape_runs, scrape_progress, app_queue, email_log.

  2. Collect your IONOS detailsmy.ionos.com

    GitHub needs three things to publish the site for you. Write them down for step 3.

    • Hosting → your web hosting package → SFTP & SSH. Note the Host (looks like home123456789.1and1-data.host) and the User name. Set or reset the password if you don't have it. The protocol is SFTP, port 22; IONOS does not offer plain FTP or FTPS for this.
    • Domains & SSL → click jobs.lisaney.com. Note the Directory it points at, for example /jobs. That folder is where the site goes.
    • On the same page, make sure an SSL certificate is active for jobs.lisaney.com, so the site loads over https.
    Expect

    A host, a user name, a password, and a directory.

  3. Add the GitHub secretsgithub.com/lisaneykong/orbital → Settings

    Repo → Settings → Secrets and variables → Actions → New repository secret, once per row. Names must match exactly. A saved secret can't be read back; if unsure, overwrite it.

    • SUPABASE_URL: https://<your-ref>.supabase.co (Supabase → Settings → API)
    • SUPABASE_SERVICE_ROLE_KEY: the service_role / sb_secret_ key, never the anon / publishable one
    • IONOS_FTP_SERVER, IONOS_FTP_USERNAME, IONOS_FTP_PASSWORD: the host, user and password from step 2
    • IONOS_REMOTE_PATH: the directory from step 2, for example /jobs. Leave it out only if the SFTP user already lands in that folder
    • Optional, for the morning Apply Queue: ANTHROPIC_API_KEY (an account with credits, about 5 cents per prepared role)
    • Optional, for the 8 AM email: RESEND_API_KEY, plus EMAIL_FROM once lisaney.com is verified in Resend, and EMAIL_TO (defaults to one@lisaney.com)
    !

    The most common failure is the anon key pasted into SUPABASE_SERVICE_ROLE_KEY. The anon key can only read, so the scraper finds jobs and can't save them. The workflow checks this first and says so.

    Expect

    Six secrets minimum (two Supabase, four IONOS). Eight with the Apply Queue and the email.

  4. Upload the files to GitHubgithub.com/lisaneykong/orbital

    Upload the contents of this folder to the top level of the repo, not the folder itself. This upload also publishes the site to IONOS.

    • In Windows File Explorer, turn on View → Show → Hidden items, so the .github folder and .htaccess are included
    • Repo home → Add file → Upload files → drag in everything in this folder → Commit changes
    • Open .github/workflows/: there should be exactly three files, scrape.yml, deploy.yml and daily-email.yml. Delete any other workflow, and any stray scrape.yml at the repo top level
    • Delete SUPABASE-TELEMETRY-ONLY.sql and SUPABASE-APPLY-QUEUE.sql if the repo still has them; SUPABASE-SCHEMA.sql replaces both

    Compare against MANIFEST.txt if anything seems missing. It flags the hidden files most upload tools skip.

    Expect

    A new commit, exactly three workflow files, and .htaccess visible in the file list.

  5. Check the site went livegithub.com → Actions

    The upload started a run called Publish website to IONOS. It turns green only when jobs.lisaney.com is actually serving the new files.

    • Repo → Actions → the newest Publish website to IONOS run. Wait for the green tick (about a minute)
    • Open jobs.lisaney.com → Settings: the build should read 2026-10-19.1

    If it's red: "Repo secrets not set" means a step 3 name is wrong. "not serving" means the files went to a different folder than the site uses: set IONOS_REMOTE_PATH to the directory from step 2, then Re-run all jobs.

    Expect

    A green run and build 2026-10-19.1 on the live site.

  6. Check the job boards, then fill the boardgithub.com → Actions

    First a health check that writes no jobs, then the real scrape.

    • Repo → Actions → Orbital daily scrape → Run workflow → mode diagnose → Run workflow
    • Open the run → scrape job → Run scraper. It lists every board as PASS, EMPTY or FAIL with the reason, then checks the six tables and that the key can write. failed-scrapes-log under Artifacts has the same list as a spreadsheet
    • Run the workflow again with mode full. From then on it runs by itself every morning at 6 AM Central
    • Open pipeline-probe.html on the live site to see the run land
    Expect

    A green full run, roles on jobs.lisaney.com, and a done row in scrape_runs with rows written.
